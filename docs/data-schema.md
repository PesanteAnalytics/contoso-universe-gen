# Data Schema

> The 7 tables generated by CUG, their columns, data types, and foreign key relationships.

---

## Data Model (Star Schema)

CUG generates a classic star schema with **1 fact table** and **6 dimension tables**.

```
                         ┌─────────────────┐
                         │    DimDate       │
                         │  (DateKey PK)    │
                         └────────┬─────────┘
                                  │ OrderDateKey, DeliveryDateKey
                                  │
┌──────────────────┐     ┌────────┴─────────┐     ┌──────────────────┐
│   DimCustomer    │     │                  │     │   DimProduct     │
│ (CustomerKey PK) │─────│    FactSales     │─────│ (ProductKey PK)  │
└──────────────────┘     │                  │     └──────────────────┘
                         └────────┬─────────┘
                                  │
                         ┌────────┴─────────┐
                         │    DimStore       │
                         │  (StoreKey PK)    │
                         └────────┬─────────┘
                                  │
                         ┌────────┴─────────┐
                         │   DimCurrency     │
                         │ (CurrencyKey PK)  │
                         └────────┬─────────┘
                                  │
                         ┌────────┴──────────────┐
                         │  DimCurrencyExchange   │
                         │ (CurrencyCode+Date PK) │
                         └────────────────────────┘
```

## Dimension Tables

### `DimDate` — Calendar

Complete calendar covering the entire configured time range (default: 2018-01-01 to 2026-12-31).

| Column | Type | Description |
|--------|------|-------------|
| `DateKey` | `Int32` | Primary key (format `YYYYMMDD`, e.g. `20240115`) |
| `Date` | `Date` | Full date |
| `Year` | `Int16` | Year (e.g. `2024`) |
| `Quarter` | `Int8` | Quarter (1–4) |
| `Month` | `Int8` | Month (1–12) |
| `MonthName` | `String` | Month name (localized by language) |
| `Day` | `Int8` | Day of the month (1–31) |
| `DayOfWeek` | `Int8` | Day of the week (0=Mon ... 6=Sun) |
| `DayName` | `String` | Day name (localized) |
| `WeekOfYear` | `Int8` | Week of the year (1–53) |
| `IsWeekend` | `Boolean` | Saturday or Sunday |
| `IsHoliday` | `Boolean` | Holiday for the configured country |

### `DimCustomer` — Customers

Pool of synthetic customers, 100% NumPy-vectorized.

| Column | Type | Description |
|--------|------|-------------|
| `CustomerKey` | `Int32` | Primary key |
| `GeoAreaKey` | `Int32` | Geographic area key |
| `StartDT` | `String` | Customer start date |
| `EndDT` | `String` | Customer end date (null = active) |
| `Continent` | `String` | Continent |
| `Gender` | `String` | Gender (`M`, `F`, `Other`) |
| `Title` | `String` | Title (e.g. `Sr.`, `Dr.`) |
| `GivenName` | `String` | First name (localized) |
| `MiddleInitial` | `String` | Middle initial |
| `Surname` | `String` | Last name (localized) |
| `StreetAddress` | `String` | Street address |
| `City` | `String` | City (localized) |
| `State` | `String` | State code |
| `StateFull` | `String` | State full name |
| `ZipCode` | `String` | Zip / postal code |
| `Country` | `String` | Country code (ISO) |
| `CountryFull` | `String` | Country full name |
| `Birthday` | `String` | Date of birth (ISO) |
| `Age` | `Int32` | Age in years |
| `Occupation` | `String` | Occupation |
| `Company` | `String` | Company name |
| `Vehicle` | `String` | Vehicle model |
| `Latitude` | `Float64` | Latitude |
| `Longitude` | `Float64` | Longitude |

> [!NOTE]
> The `pool_size` in the configuration controls how many unique customers are generated. Only `active_pct` of them will have at least one purchase.

Product catalog organized by category and subcategory.

| Column | Type | Description |
|--------|------|-------------|
| `ProductKey` | `Int32` | Primary key |
| `ProductCode` | `String` | Product code (e.g. `PROD-00001`) |
| `ProductName` | `String` | Product name (localized) |
| `Manufacturer` | `String` | Manufacturer |
| `Brand` | `String` | Product brand |
| `Color` | `String` | Product color |
| `WeightUnit` | `String` | Weight unit (`lb`, `kg`, `oz`, `g`) |
| `Weight` | `Float64` | Product weight |
| `Cost` | `Float64` | Unit cost in USD |
| `Price` | `Float64` | Unit price in USD |
| `CategoryKey` | `Int32` | Category key |
| `CategoryName` | `String` | Category name (e.g. Electronics, Home) |
| `SubCategoryKey` | `Int32` | Subcategory key |
| `SubCategoryName` | `String` | Subcategory name (e.g. Laptops, Headphones) |

### `DimStore` — Stores

Physical stores and online channel.

| Column | Type | Description |
|--------|------|-------------|
| `StoreKey` | `Int32` | Primary key |
| `StoreCode` | `Int32` | Numeric store code |
| `GeoAreaKey` | `Int32` | Geography area key |
| `CountryCode` | `String` | ISO country code (or `ONLINE`) |
| `CountryName` | `String` | Country name |
| `State` | `String` | State / Province |
| `OpenDate` | `String` | Opening date (ISO format) |
| `CloseDate` | `String` | Close date (null = active) |
| `Description` | `String` | Store display name |
| `SquareMeters` | `Int32` | Square meters (physical stores only) |
| `Status` | `String` | Status: `Online`, `Current`, or `Closed` |

### `DimCurrency` — Currencies

Currencies supported in the dataset.

| Column | Type | Description |
|--------|------|-------------|
| `CurrencyKey` | `Int32` | Primary key |
| `CurrencyCode` | `String` | ISO 4217 code (e.g. `USD`, `EUR`) |
| `CurrencyName` | `String` | Currency name |

---

### `DimCurrencyExchange` — Exchange Rates

Daily exchange rates against USD.

| Column | Type | Description |
|--------|------|-------------|
| `Date` | `String` | Rate date (ISO format) |
| `FromCurrency` | `String` | Source currency (always `USD`) |
| `ToCurrency` | `String` | Target currency code |
| `Exchange` | `Float64` | Exchange rate (1 USD = X units) |

## Fact Table

### `FactSales` — Sales

The main fact table. Each row represents a sales order line.

| Column | Type | Description |
|--------|------|-------------|
| `OrderKey` | `Int64` | Unique order identifier |
| `LineNumber` | `Int32` | Line number within the order |
| `OrderDate` | `String` | Order date (ISO format) |
| `DeliveryDate` | `String` | Delivery date (ISO format) |
| `CustomerKey` | `Int32` | FK → DimCustomer |
| `StoreKey` | `Int32` | FK → DimStore |
| `ProductKey` | `Int32` | FK → DimProduct |
| `Channel` | `String` | Sales channel (`Online` or `Store`) |
| `Quantity` | `Int32` | Quantity purchased |
| `UnitPrice` | `Float64` | Unit price at time of sale |
| `NetPrice` | `Float64` | Net price after adjustments |
| `UnitCost` | `Float64` | Unit cost at time of sale |
| `CurrencyCode` | `String` | Currency code (FK → DimCurrency) |
| `ExchangeRate` | `Float64` | Exchange rate applied |

## Foreign Key (FK) Relationships

| FK in FactSales | → Dimension | Key |
|-----------------|-------------|-----|
| `OrderDate` | `DimDate` | `DateKey` |
| `DeliveryDate` | `DimDate` | `DateKey` |
| `CustomerKey` | `DimCustomer` | `CustomerKey` |
| `ProductKey` | `DimProduct` | `ProductKey` |
| `StoreKey` | `DimStore` | `StoreKey` |
| `CurrencyCode` | `DimCurrency` | `CurrencyCode` |

## Integrity Validation

CUG can validate referential integrity **in memory** before writing. To enable this validation:

```toml
[output]
integrity_check  = true    # Enable validation
integrity_strict = true    # Abort on violations (or false for report only)
```

Or from the command line:

```bash
cug generate --strict       # Validate and abort on errors
cug generate --no-strict    # Validate and report, but continue
```

## Approximate Data Volume

The `target_orders` controls the number of orders generated. Here is a volume guide:

| target_orders | FactSales (approx. rows) | DimCustomer | Approx. Parquet size |
|--------------|------------------------|--------------|-----------------------|
| 5,000 | ~8K–12K | ~15K | ~2 MB |
| 100,000 | ~160K–240K | ~50K | ~30 MB |
| 1,000,000 | ~1.6M–2.4M | ~50K | ~250 MB |
| 10,000,000 | ~16M–24M | ~50K | ~2.5 GB |

> [!NOTE]
> `FactSales` has more rows than orders because each order can have multiple lines (products).
